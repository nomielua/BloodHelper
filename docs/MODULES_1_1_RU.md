# Новые модули BLOODHELPER 1.1.0+1.21.11

Версия добавляет **Notifications, Item Counter, Armor HUD, Performance
и Session Stats**. Cooldowns, PvP Timer и Dynamic Island с текстами песен
сохраняются. Это описание поведения целевой версии во время интеграции,
а не объявление релиза или отчёт о прошедших проверках.

Все пять новых модулей включены в исходной конфигурации. Их карточки в Visuals
по умолчанию свёрнуты; раскрытие карточки и включение модуля — разные действия.
Восемь карточек расположены в двух колонках, настройки раскрываются внутри
них. Названия английские, пояснения по умолчанию русские.

Каждый новый HUD можно перемещать и масштабировать в HUD Editor. Масштаб
сохраняется отдельно, диапазон 50–200%; при нехватке места блок дополнительно
уменьшается до размеров окна. Есть выравнивание и привязка к краю, собственные
Background и Text shadow. Общие переключатели фона и тени в Appearance имеют
приоритет. Все текстовые поля используют существующий CustomFont из OTF,
включая числа, проценты, `∞`, `—` и уведомления. Файлы шрифтов и маски иконок
сохраняются. Подробнее: [HUD_DESIGN_RU.md](HUD_DESIGN_RU.md).

## Notifications

Краткие карточки предупреждают о трёх изменениях состояния своего игрока:

| Предупреждение | Источник | Исходный порог |
| --- | --- | --- |
| Armor | Реально надетая повреждаемая броня | 20% оставшейся прочности; настройка Armor HUD |
| Items | Выбранные в Item Counter registry ID | 3 предмета; настройка Item Counter |
| Effects | Конечные полезные эффекты игрока | 10 секунд до окончания |

Для каждого наблюдаемого значения нужна последовательность: сначала **выше
порога**, затем **на пороге или ниже**. Например, при пороге 3 изменение
количества тотемов 4 → 3 вызывает предупреждение, а 3 → 2 повторного
предупреждения не создаёт. После пополнения выше порога новое снижение может
вызвать следующую карточку.

Первое наблюдение уже низкого значения и изменение порога устанавливают
новую исходную точку без уведомления. При входе в мир есть короткий период
синхронизации инвентаря и эффектов; он также не создаёт предупреждений.
Исчезнувший эффект или снятая броня перестают наблюдаться, а возвращение
устанавливает новую исходную точку. Смена мира, игрока, подключения, смерть
или выключение Notifications очищают его состояние.

Карточки создаются по событиям пересечения порога, а не каждый кадр. Для
одного уже видимого предупреждения обновляется текст без продления времени.
По умолчанию показываются до **трёх карточек по четыре секунды**; доступны
1–4 карточки и 2–10 секунд. При превышении лимита уходят самые старые.
Звук **выключен по умолчанию**; при включении частота звука ограничивается,
чтобы одновременные предупреждения не звучали непрерывно. Test создаёт пример
только по явному нажатию.

Каждую группу предупреждений можно выключить. Скрытый Armor HUD или
Item Counter не выключает соответствующую группу Notifications: используются
те же выбранные предметы и пороги. Бесконечные, вредные и уже завершившиеся
эффекты не создают предупреждение об окончании; порог для остальных — 1–60 секунд.

**Отдельного Effects HUD нет. Vanilla-индикаторы эффектов Minecraft остаются
без изменений.**

## Item Counter

По умолчанию выбраны:

| Предмет | Registry ID |
| --- | --- |
| Тотем бессмертия | `minecraft:totem_of_undying` |
| Эндер-жемчуг | `minecraft:ender_pearl` |
| Золотое яблоко | `minecraft:golden_apple` |
| Стрела | `minecraft:arrow` |

Выбор делается через готовые варианты предметов и **Add held item**. Последняя добавляет
тип предмета в основной руке; повторяющиеся ID не создают вторую строку.
Максимум — восемь разных registry ID. Неизвестные реестру и некорректные
идентификаторы не отображаются как существующие предметы.

В готовом списке также есть зачарованное золотое яблоко, спектральная стрела,
пузырёк опыта и заряд ветра. Каждый вариант включается отдельно. Чтобы
освободить место при лимите восьми типов, сними лишний выбор; для добавленных
предметов вне готового списка доступна Remove.

Подсчитываются единицы предметов в **36 основных слотах собственного инвентаря,
включая хотбар, плюс вторая рука ровно один раз**. Основная рука уже входит
в хотбар. Слоты открытого сундука или другого контейнера, предмет на курсоре,
надетая броня и содержимое вложенных контейнеров не включаются. Открытие сундука
не превращает его содержимое в собственный запас.

Группировка идёт по registry ID, без разделения по имени, описанию, зачарованиям
или другим компонентам. Два серверных кастомных предмета на базе одного
`minecraft:...` складываются в общий счётчик. Add held item не создаёт фильтр
по кастомному названию; иконка существующего предмета может отражать его
оформление, но это не меняет способ подсчёта.

В исходной конфигурации названия выключены, нулевые значения видны,
порог малого остатка равен 3. При значении не выше порога число выделяется
цветом; диапазон порога — 0–64. Без названий используется сетка до четырёх
ячеек в ряд, с названиями — список. Hide zero скрывает нулевые строки;
если отображать нечего, игровой блок исчезает. Предпросмотр редактора
использует примеры и не меняет инвентарь.

## Armor HUD

Показываются четыре реальные позиции экипировки: шлем, нагрудник, поножи
и ботинки. Запасные предметы в инвентаре не заменяют надетые в этом HUD.
Иконка и название берутся из надетого предмета, а прочность — из его данных.

| Состояние | Значение |
| --- | --- |
| Повреждаемый предмет, режим Percent | Оставшийся процент с округлением вверх |
| Повреждаемый предмет, режим Points | Оставшиеся единицы прочности |
| Неразрушимый предмет | `∞` |
| Пустой слот или предмет без прочности | `—` |

Для повреждаемых предметов есть полоса остатка. Низкая прочность выделяется
цветом при фактической доле не выше порога; округление процента не меняет
само сравнение. Порог по умолчанию **20%**, допустимы 1–90%. Его используют
и предупреждения Notifications. Пустые, неразрушимые и не имеющие прочности
предметы не дают предупреждений о низкой прочности.

По умолчанию выбран Percent, названия скрыты, полностью пустой блок скрывается.
В компактном виде видны четыре ячейки; при включении названий — четыре строки.
Положение, масштаб, фон и тень настраиваются отдельно.

## Performance

| Поле | Что означает |
| --- | --- |
| FPS | Фактический показатель частоты кадров клиента Minecraft |
| Frame | Средний измеренный интервал между кадрами в мс по накопленной короткой истории |
| График | История интервалов кадров; новые значения справа |
| Ping | Задержка из полученных клиентом данных о своём игроке в списке игроков, если она доступна |

В исходной конфигурации включены все три поля и график. История вмещает
до 90 интервалов. Frame измеряется по времени между кадрами, а не подставляется
как `1000 / FPS`; он включает ожидания между кадрами активной игры и не является
отдельным измерением времени CPU или GPU.

Открытый экран интерфейса, игровая пауза, отсутствие мира/игрока и отключённый
модуль приостанавливают сбор кадровой истории и очищают её. Разрыв больше
секунды также сбрасывает историю, поэтому возврат после паузы не становится
искусственным пиком. Пока нет данных, FPS или Frame могут отображаться как `—`.
Демонстрационный график в редакторе не выдаётся за реальные измерения.

Ping обновляется с доступными клиенту сведениями о своём игроке; отдельный
сетевой запрос ради этого показателя не отправляется. При отсутствии сведений
показывается `—`, а не придуманное число. **TPS сервера не измеряется** и
не выводится из FPS, интервалов кадров или ping.

## Session Stats

Режим выбирается вручную: **FFA / SMP / MEETUPS**, по умолчанию **FFA**.
Модуль хранит локальное состояние наблюдаемой сессии; это не история аккаунта
или статистика, запрошенная из серверной базы. Источники режимов различаются.

### FFA

HUD показывает только **Total kills** (всего убийств), **Rewarded kills**
(убийств с монетной наградой) и необязательное **Time**. Rewarded — число
награждённых убийств, а не сумма монет. Смерти, K/D и серия в этом режиме
не отображаются.

Основание для распознавания — ровно два формата, представленные пользователем
на снимках [награды](evidence/session-formats/ffa-reward.png) и
[отказа в награде](evidence/session-formats/ffa-no-reward.png). Текст первого
примера ниже приведён без декоративного значка перед ником; значок виден
в исходном изображении.

```text
[21:39:30] Ты получил 18 монет за убийство игрока HumsterMangok с множителем x1.5
[21:39:40] За этого игрока пока нельзя получить монеты. Подожди 340 секунд
```

| Полученный формат | Total kills | Rewarded kills |
| --- | --- | --- |
| Монеты за убийство игрока с множителем | +1 | +1 |
| За этого игрока пока нельзя получить монеты | +1 | Без изменения |

Распознавание сопоставляет полную фразу. Число монет, ник, множитель и время
ожидания — переменные части указанных форматов. Необязательный префикс времени,
коды оформления, пробелы и декоративный значок перед ником учитываются
при обработке; это не поиск произвольной подстроки «монеты» или «убийство».

Принимаются серверные игровые сообщения, не обычные сообщения игроков
и не текст action bar. Другие объявления об убийствах и смертях в FFA
игнорируются, чтобы не добавлять второе убийство по другому источнику.
Покупка, начисление монет по другой причине и неподходящая фраза не увеличивают
счётчики. Пользовательский шаблон SMP / MEETUPS на FFA не распространяется.

Засчитывание отказа в награде — явная договорённость для этого FFA: такое
сообщение считается подтверждением убийства без монет, хотя само по себе
не содержит ника жертвы. Поэтому точность зависит от того, что сервер
использует его именно в этом смысле. Отсутствующее сообщение не восстанавливается
по удару, смерти рядом стоящего игрока или изменению баланса. Смена серверного
формата может привести к пропуску события; общие догадки вместо формата
не применяются.

Повторная доставка одного и того же сообщения подавляется в пределах
недавней истории обработки.
Два отдельных сообщения с одинаковым текстом могут обозначать два убийства
и не объединяются только по совпадению текста. Если сервер повторно присылает
один результат как новое сообщение, без уникального идентификатора события
клиент не может надёжно отличить его от нового убийства.

**Эти изображения — пользовательские примеры серверных форматов. Они
не подтверждают запуск BLOODHELPER, прохождение тестов или проверку на сервере.**

### SMP и MEETUPS

Оба режима используют стандартные поля **Kills, Deaths, K/D, Streak**
и необязательное время. Счётчик убийств принимает поддерживаемые стандартные
сообщения Minecraft о смерти игрока с явно указанным убийцей, когда убийцей является
локальный игрок. Учитывается структура события, а не поиск похожих слов
в произвольном тексте. Данные списка игроков помогают исключить жертв-мобов.

Если сервер заменяет стандартные сообщения своим текстом, можно задать
буквальный шаблон с **одним `{killer}` и одним `{victim}`**. Например,
`{killer} победил {victim}` — только пример настройки, не заявленный формат
Bloodstone. В текущем конфиге шаблон хранится в `session.killMessageTemplate`
файла `config/bloodhelper/client.json` внутри профиля Minecraft. Для ручной
настройки закрой игру и задай это строковое значение в JSON; отдельное поле
в меню не требуется для работы параметра.
Сопоставление охватывает всю строку; это не регулярное выражение.
Шаблон по умолчанию пуст и не включает эвристику по чату. Сообщения игроков
не служат источником, даже если их текст совпадает с шаблоном. Серверный плагин,
пересылающий пользовательский текст как игровые сообщения, может размывать
это различие; шаблон должен соответствовать именно собственному сообщению
сервера.

Смерть определяется по переходу состояния собственного игрока «жив → мёртв»
во время активного наблюдения. Сообщение о смерти не прибавляет её второй раз.
Убийство увеличивает серию, если локальный игрок жив; собственная смерть
сбрасывает серию. K/D вычисляется из накопленных убийств и смертей: при
положительном числе убийств без смертей выводится `∞`, при двух нулях — `0.00`.

Пока клиент не получил поддерживаемое сообщение об убийстве, Kills, K/D
и Streak показывают `—` с пояснением об отсутствии данных; смерти и время
могут учитываться независимо. Недоступная лента убийств, скрытые сервером
сообщения, нестандартный формат или неподходящий шаблон могут дать неполную
статистику. Модуль не считает удар, исчезновение сущности или догадку об исходе
боя подтверждённым убийством.

### Время и сброс

По умолчанию время включено. Оно накапливается при активном подключении,
включённом модуле и отсутствии игровой паузы; отключение от сервера и пауза
не добавляют время. Выключенный модуль не наблюдает события задним числом.
Открытое меню BLOODHELPER само по себе не ставит мир на паузу.

**Смена режима всегда сбрасывает счётчики и время**, в том числе при загрузке
профиля с другим режимом. Ручной Reset session начинает сессию заново. По умолчанию
Disconnect reset включён. Если выключить его, состояние можно продолжить
при возврате тем же игроком на тот же сервер или в тот же локальный мир;
смена сервера, мира одиночной игры или игрока начинает новую сессию.
Промежуточная загрузка и смена измерения сами по себе не равны смене сервера.
Профили сохраняют параметры, а не историю сессии; перезапуск клиента
не восстанавливает накопленные числа.

## Статус проверки и происхождение

Результаты сборки, автоматических тестов, проверок интерфейса и отдельного
локального мира приведены в [VERIFICATION_RU.md](VERIFICATION_RU.md).
Пользовательские сообщения FFA проверяются в воспроизведённом сценарии;
это не проверка подключения к живому серверу Bloodstone.

Изменение серверов не требуется. Все пять модулей используют состояние,
уже доступное клиенту. Историческое происхождение визуальных ресурсов
и прежних функций сохранено в [README_RU.md](../README_RU.md),
[EXPENSIVE_GUI_RU.md](EXPENSIVE_GUI_RU.md) и
[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).
