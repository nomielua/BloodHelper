# Музыка Windows в BLOODHELPER

`MediaService` читает выбранную Windows медиасессию через штатный API GSMTC.
Требования: Windows 10 версии 1809 или новее / Windows 11, штатный Windows
PowerShell 5.1 и приложение, которое публикует медиасессию Windows.
Проигрыватель и трек мод самостоятельно не запускает.

Внутри JAR находится `bloodhelper/media-bridge.ps1`. При `start()` сервис
извлекает его в собственную случайную папку `%TEMP%/bloodhelper/media-*`
и запускает один фоновый процесс штатного PowerShell без профиля.
Параметр `-ExecutionPolicy Bypass` относится только к этому процессу:
постоянная политика системы и файлы профиля не меняются. После завершения
клиента процесс останавливается, временная копия удаляется по возможности.
Нативные библиотеки, EXE и дополнительные пакеты из сети не скачиваются.

Каждые примерно 500 мс читаются название, исполнитель, положение, длительность
и состояние воспроизведения. Текущую сессию выбирает Windows: мод использует
`GetCurrentSession()`. Если открыто несколько проигрывателей, это может быть
последнее выбранное системой приложение, а не Spotify.

Обложка читается при смене трека и перепроверяется раз в 5 секунд.
Размер ограничен 2 МиБ. Пустые, слишком большие или недоступные обложки
пропускаются; название и прогресс при этом продолжают работать. На сторону
Minecraft передаются исходные байты изображения; создание и удаление
текстуры выполняет HUD на потоке рендера. Потребитель должен читать
`snapshot.artwork()` только при изменении `snapshot.revision()`: этот метод
возвращает защитную копию массива.

Положение рассчитывается от начала временной шкалы. Во время проигрывания
учитывается время с последнего обновления Windows и опубликованная скорость.
Во время паузы позиция не увеличивается. Длительность 0 означает, что
приложение её не предоставило, например для прямого эфира. Точность зависит
от данных, которые публикует проигрыватель. `snapshot()` возвращает готовое
значение без ожидания и выделения памяти; обновления приходят два раза в секунду.

`playPause()`, `previous()` и `next()` только ставят явное действие пользователя
в ограниченную очередь. PowerShell вызывает соответствующий метод GSMTC,
если приложение сообщает поддержку команды. Максимум 16 ожидающих команд,
срок ожидания 2 секунды. При разрыве соединения очередь очищается, команды
после переподключения не повторяются. Команды могут быть отклонены самим
проигрывателем. Они не имитируют клавиатурные нажатия.

Все операции с процессом, JSON, WinRT и изображениями выполняются в фоновых
потоках. У WinRT есть тайм-аут 3 секунды, у зависшего процесса — 20 секунд.
После сбоя соединение повторяется с растущей задержкой до 30 секунд.
Пакет JSON ограничен 3 МиБ, диагностическая строка — 512 символами.
Метаданные песен намеренно не записываются в лог.

На Linux, macOS и при запуске Java внутри WSL сервис не запускает никаких
процессов и возвращает `unsupported_os`. Поддержка MPRIS в этой версии
не реализована. Обычный Minecraft, запущенный из Windows, использует Windows
ветку независимо от того, где собирался JAR.

API интеграции:

```java
MediaService media = new MediaService();
media.setEnabled(true);            // Включить или возобновить модуль музыки.
MediaSnapshot now = media.snapshot();
media.playPause();                 // Только после нажатия пользователем.
media.setEnabled(false);           // Остановить мост, очистить данные и команды.
media.close();                     // Окончательное завершение клиента.
```

Статусы: `stopped`, `unsupported_os`, `starting`, `no_session`, `playing`,
`paused`, `unavailable`. `setEnabled` можно вызывать каждый тик: повторное
значение не создаёт процесс и не меняет снимок. Отключение и повторное
включение используют тот же объект сервиса, но отдельные сессии с отдельными
очередями команд. Завершившаяся старая сессия не может перезаписать новые
данные. Номер обложки продолжает увеличиваться между включениями.
`close()` окончательный; для нового запуска после него нужен новый объект.
PowerShell запускается с `-WindowStyle Hidden`. Смена сервера не требует остановки:
медиасессия относится к Windows, а не к игровому миру. Получение текстов
песен и переключатель «с текстом / без текста» реализуются модулем музыки
отдельно; сам медиасервис не отправляет сетевых запросов.

Проверки:

- `MediaBackendSelfTest` проверяет JSON, сброс старой обложки при смене трека,
  защиту массива, изменение revision, ограничения размеров, позицию, EOF
  и отключение сервиса на неподдерживаемой ОС. Он не управляет проигрывателем.
- `media-bridge.ps1 -ReadOnlySamples 3` — диагностический режим на Windows.
  Он читает три снимка, не принимает управляющих команд и завершается.
  Стандартный вывод содержит метаданные текущей песни: не публикуйте его
  целиком при диагностике, если названия являются личными данными.

Локальная проверка 12 октября 2026: чистая компиляция Java с `--release 21`,
все проверки `MediaBackendSelfTest` прошли. На реальной Windows медиасессии
получены три последовательных снимка с одинаковой позицией на паузе и
обложкой 36 275 байт; обложка передавалась только в первом снимке.
Закрытие stdin завершило длительно работающий мост с кодом 0 и без stderr.
Отдельно проверено чтение синтетического PNG через WinRT. Команды управления
реальным проигрывателем и показ текстуры в Minecraft этой проверкой не проверялись.

Проверка `MediaLifecycleReadOnlyProbe --windows-read-only` под Windows Java 21
подтвердила включение, выключение, повторное включение того же объекта,
окончательный `close()`, защиту от старых данных и отмену во время запуска.
После завершения дочерние процессы PowerShell и временные копии скрипта
отсутствовали. Проба читала медиасессию, но не отправляла команды плееру.
